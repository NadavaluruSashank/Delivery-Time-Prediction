# Delivery Time Prediction System

An end-to-end machine learning project that predicts delivery time for logistics orders from order and route features, and serves the model through a REST API.

> **Simulated data.** The dataset is generated by `src/data_generator.py`. It is not real business data, and the results below are not from a real deployment.

---

## Problem Statement

Inaccurate delivery-time estimates make planning harder and frustrate customers. This project builds the full path from data to a served prediction: a model that estimates delivery time from distance, vehicle type, weather, traffic and time of day, exposed through a REST API.

---

## Solution Overview

| Stage | Details |
|---|---|
| Data Simulation | Realistic delivery order generator — 5,000 orders with distance, traffic, weather, vehicle type |
| Feature Engineering | Cyclical hour encoding, rush-hour flags, one-hot categorical encoding |
| Model Training | XGBoost Regressor with train/test split and evaluation |
| Evaluation | MAE, RMSE, R² on held-out test set |
| Deployment | Flask REST API — accepts JSON input, returns predicted delivery time |

---

## Dataset

- **Type:** simulated. `src/data_generator.py` creates 5,000 orders with distance, order hour, vehicle type (bike, scooter, car, van), weather (clear, rain, fog, storm) and traffic density (low, medium, high).
- **Target:** delivery time in minutes, produced by the generator from those features plus random noise.
- The saved copy is `data/delivery_orders.csv`.

## Architecture

```
data_generator.py -> data/delivery_orders.csv -> preprocess.py (feature engineering)
                  -> train.py (XGBoost, 80/20 split) -> models/*.pkl -> predict.py -> app/app.py (Flask POST /predict)
```

## Tech Stack

- **ML:** XGBoost, Scikit-learn

## Model Performance

Trained and evaluated on 5,000 simulated delivery orders (80/20 train-test split). Re-run in November 2026 with XGBoost 3.4.1 and scikit-learn 1.9.1, the script reproduced the same numbers:

| Metric | Value |
|---|---|
| MAE (Mean Absolute Error) | 3.25 minutes |
| RMSE | 4.08 minutes |
| R² Score | 0.974 |

**Top predictive features:** traffic density, distance, vehicle type (bike vs. car/van), and weather conditions.

## API Usage

**Endpoint:** `POST /predict`

**Request:**
```json
{
  "distance_km": 5.2,
  "order_hour": 12,
  "vehicle_type": "scooter",
  "weather_condition": "clear",
  "traffic_density": "medium"
}
```

**Response:**
```json
{
  "predicted_delivery_time_minutes": 22.8,
  "input": {
    "distance_km": 5.2,
    "order_hour": 12,
    "vehicle_type": "scooter",
    "weather_condition": "clear",
    "traffic_density": "medium"
  }
}
```

**Valid values:**
- `vehicle_type`: bike, scooter, car, van
- `weather_condition`: clear, rain, fog, storm
- `traffic_density`: low, medium, high
- `order_hour`: 0–23

## How to Run

```bash
# Clone the repository
git clone https://github.com/NadavaluruSashank/Delivery-Time-Prediction.git
cd Delivery-Time-Prediction

# Install dependencies
pip install -r requirements.txt

# 1. Generate simulated delivery order data
python src/data_generator.py

# 2. Train the model
cd src && python train.py && cd ..

# 3. Test a single prediction
cd src && python predict.py && cd ..

# 4. Start the REST API
python app/app.py
```

Once running, test the API with curl:
```bash
curl -X POST http://127.0.0.1:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"distance_km": 8.5, "order_hour": 18, "vehicle_type": "bike", "weather_condition": "rain", "traffic_density": "high"}'
```

## Limitations

- The data is simulated, and the target is generated from the same features the model uses, so a high R² is expected. It says the pipeline works, not that the model would be this accurate on real deliveries.
- Random 80/20 split; real delivery data would need a time-based split.
- No monitoring, retraining or authentication on the API: it is a local demo.

## Possible applications

The same pipeline shape (features → model → API) applies to ETA estimates for last-mile delivery, food delivery or e-commerce, once trained on real data.
